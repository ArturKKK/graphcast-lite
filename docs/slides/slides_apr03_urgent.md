# Повышение точности регионального прогноза погоды в графовой нейросетевой модели

**Доклад по GraphCast-lite для Красноярского региона**

Подготовил: Табаков Артур Станиславович
Научный руководитель: Пененко А.В., д.ф.-м.н., ВНС ИВМиМГ СО РАН

---

## Постановка проблемы

1. **Накопление ошибки.** В авторегрессионном режиме нейросеть быстро теряет точность без коррекции траектории прогноза.
2. **Разреженность наблюдений.** Реальная сеть метеостанций покрывает лишь малую часть региона; нужно восстанавливать поля в «слепых зонах».
3. **Граничные артефакты.** Вырезание региона из глобальной сетки приводит к потере информации на границах.
4. **Несовпадение масштабов.** Глобальная сетка нужна для крупномасштабной динамики, а локальная детализация — для прогноза над Красноярском.

---

## Цель и задачи

**Цель:** повысить точность краткосрочного прогноза погоды над Красноярском в рамках графовой нейросетевой модели.

**Задачи:**

1. Реализовать глобальную GNN-модель на базе архитектуры GraphCast.
2. Построить мультирезолюционную схему: глобальный граф + региональная подсетка 0.25°.
3. Подобрать устойчивую стратегию fine-tune с заморозкой Processor.
4. Исследовать усвоение данных: Nudging и Optimal Interpolation.
5. Разработать каскадный downscaler (UNet) для пространственного уточнения.
6. Верифицировать модель на ERA5 и в живом прогнозе по GDAS.

---

## Базовая модель: GraphCast-lite

- **Encoder:** проекция признаков с регулярной grid-сетки на икосаэдральную mesh.
- **Processor:** message passing на mesh, обновление рёбер и узлов через MLP.
- **Decoder:** обратная проекция прогноза на регулярную сетку.

**Processor = Interaction Network:**

- Edge MLP принимает фичи двух узлов и ребра, формируя сообщение.
- Node MLP принимает фичи узла и агрегат входящих сообщений.
- 12 шагов message passing, скрытая размерность 256.

**Почему GNN:** сферическая геометрия Земли обрабатывается естественно, без искажений прямоугольной сетки на полюсах.

---

## Набор переменных и метрики

Используем **19 полей ERA5**: t2m, 10u, 10v, msl, tp, sp, tcwv, z_surf, lsm, а также t/u/v/z/q на 850 и 500 гПа.

Основные метрики:

- **RMSE:** среднеквадратичная ошибка в физических единицах.
- **Skill:** $1 - \text{RMSE}_{\text{model}} / \text{RMSE}_{\text{persistence}}$.
- **ACC:** корреляция аномалий.
- **Persistence:** бейзлайн «следующий шаг равен последнему наблюдению».

ERA5 используется как ground truth для offline-оценки, GDAS — для live-режима.

## Мультирезолюционный подход

Вместо вырезания региона мы объединяем глобальные и региональные узлы в **единую плоскую multires-сетку**:

- Глобальная подсетка: 512 × 256 = 131 072 узла (шаг ~0.7°)
- Региональная подсетка (Красноярск): 61 × 41 = 2 501 узел (шаг 0.25°)
- Итого: **133 279 узлов**, единый граф

**Преимущества:**
- Нет искусственных границ — глобальные узлы обеспечивают естественный контекст.
- Региональные узлы дают локальную детализацию в 3× выше.
- Encoder/Decoder работают с объединённой сеткой, Processor — на единой mesh.

Зона оценки локальных метрик: **45 внутренних узлов** вокруг Красноярска.

---

## Сшивание глобальных и региональных данных

При построении multires-датасета для теста и инференса используется **merge-режим**: реальные региональные поля 0.25° сшиваются с глобальным полем.

Принцип сшивания:

$$X(v) = \begin{cases} X_{\text{global}}(v), & v \notin \text{ROI} \\ X_{\text{regional}}(v), & v \in \text{ROI} \end{cases}$$

- $X_{\text{global}}$ — глобальное поле на грубой сетке 0.7°
- $X_{\text{regional}}$ — региональное поле на сетке 0.25°
- ROI — целевой регион (~55°–57°N, 90°–95°E)
- $v$ — узел объединённой сетки

> Ключевая идея: это не интерполяция, а замена грубых узлов внутри ROI реальными fine-данными.

## Стратегия дообучения: freeze6

**Проблема:** fine-tune на мультирезолюционных данных может привести к «забыванию» глобальной физики (catastrophic forgetting).

**Решение:**
1. **Первые 6 эпох:** Processor заморожен, обучаются Encoder и Decoder.
2. **Затем:** Processor размораживается с пониженным learning rate (×0.1).

Результат на 200 тестовых сэмплах:

| Метрика | freeze6 | nofreeze |
|---|---:|---:|
| Skill (глобально) | **66.9%** | 65.2% |
| Skill (регион) | **75.8%** | 74.5% |
| ACC (глобально) | **0.983** | 0.981 |

По t2m RMSE в регионе при +24ч: **1.40°C** (freeze6) vs 1.82°C (nofreeze).

> Заморозка процессора критична — без неё ошибка на +24ч растёт на 30%.

## Усвоение данных: Nudging и Optimal Interpolation

Две схемы корректировки прогноза по разреженным наблюдениям (10% узлов):

**Nudging:** локальная релаксация к наблюдению.
$$x_a = x_b + \alpha \cdot M \cdot (y_{\text{obs}} - H(x_b))$$

**Optimal Interpolation:** распространение поправки через ковариационную матрицу.
$$x_a = x_b + \mathbf{K}(y_{\text{obs}} - Hx_b), \quad \mathbf{K} = \mathbf{B}H^T(H\mathbf{B}H^T + \mathbf{R})^{-1}$$

Оптимальные параметры OI: $L = 300$ км, $\sigma_o = 0.5$, $\sigma_b = 0.8$.

---

## Сравнение алгоритмов по группам переменных

| Группа | Nudging (Skill) | OI (Skill) | Δ OI − Nudging |
|---|---:|---:|---:|
| Temperature Only | 15.6% | 16.0% | +0.4 п.п. |
| Surface Only | 16.4% | 20.0% | +3.6 п.п. |
| Dynamics Only | 17.8% | **36.5%** | **+18.7 п.п.** |
| All Variables | 18.7% | **40.1%** | **+21.4 п.п.** |

**Выводы:**
- Усваивать только температуру недостаточно — модель «сдувает» коррекцию ветром.
- OI превосходит Nudging, особенно для динамических переменных.
- Максимальный эффект — усвоение всех переменных с OI.

## UNet downscaler: концепция каскада

**U-Net** — encoder-decoder архитектура со skip connections, восстанавливающая локальные детали при сохранении глобального контекста.

**Идея каскада:** GNN строит физически согласованный крупномасштабный прогноз, затем UNet уточняет его на fine-grid (0.25°).

**Формула каскада:**
$$y_{\text{fine}} = y_{\text{coarse}}^{\uparrow} + F_{\text{UNet}}(y_{\text{coarse}}^{\uparrow}, \, s)$$

- $y_{\text{coarse}}^{\uparrow}$ — билинейно увеличенный coarse прогноз GNN
- $s$ — статические поля (рельеф, маска суша/море)
- $F_{\text{UNet}}$ — предсказанная поправка (residual)

Параметры UNet: **7 808 211** весов, base_filters = 64, вход: 40 каналов, выход: 19 полей.

## Заключение

1. Реализована глобальная GNN-модель прогноза погоды (512×256, 19 переменных, Skill 62%).

2. Предложен мультирезолюционный подход с merge-сшиванием данных; Skill в регионе — **75.8%**.

3. Стратегия заморозки процессора снижает RMSE t2m на +24ч на **0.42°C**.

4. OI превосходит Nudging; pilot DA снижает RMSE с 0.73 до **0.43°C**.

5. UNet-каскад полезен селективно: +83% по осадкам, но не улучшает t2m в offline.

6. В live-прогнозе 03.04.2026 GNN + postproc: MAE **1.77°C** vs Open-Meteo.

**Основной резерв качества** — аккуратное усвоение данных, а не агрессивный каскадный downscaling.
