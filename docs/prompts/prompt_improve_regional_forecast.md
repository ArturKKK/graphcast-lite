# Задача: улучшить региональный прогноз погоды на основе GNN

## Контекст проекта

GraphCast-lite — open-source реализация GNN (Graph Neural Network) для прогноза погоды,
вдохновлённая Google DeepMind GraphCast. Проект обучен на данных ERA5 (реанализ ECMWF).
Целевой регион — **Красноярск и окрестности** (50–60°N, 83–98°E).

---

## Текущая архитектура

### Модель: InteractionNet (GraphCast-style)
- **Encoder** (Grid→Mesh): MLP [256,256]→256 + GCNConv [256,256]→256
- **Processor** (Mesh↔Mesh): 12 шагов InteractionNet (dim=256, edge_dim=4), каждый шаг — unshared weights
  - Edge update: MLP_edge([sender ‖ receiver ‖ edge_feat]) → new_edge
  - Node update: MLP_node([node ‖ agg_edges]) → new_node, с LayerNorm и residual connections
- **Decoder** (Mesh→Grid): MLP [256,128]→128 + GCNConv [128,128]→19
- Активации: Swish/PReLU, LayerNorm (graph mode для рёбер, node mode для узлов)
- Mesh: двухуровневый icosahedral mesh (level 4 + level 6)
- Параметров: ~5.9M

### Грид: Multi-resolution (flat)
- **Глобальный**: 512×256 (~0.7°) = 130,778 узлов
- **Региональный**: 61×41 (0.25°) = 2,501 узел (Красноярск)
- **Итого**: 133,279 узлов, flat grid (без 2D структуры)

### Обучение
- **Данные**: ERA5 2010–2020, 6-часовой шаг
- **Стратегия**: pretrain глобальный (512×256, 80 эпох) → finetune на multires (32 эпохи):
  - Первые 6 эпох: processor заморожен (lr=1e-4)
  - С 7 эпохи: processor размораживается (lr_proc = lr×0.1)
- **AR-curriculum**: epochs→AR: 1→8 => AR=1, 9→16 => AR=2, 17→24 => AR=3, 25→32 => AR=4
- **Loss**: `roi_only_loss: true` — MSE считается ТОЛЬКО по 2,501 региональному узлу
- **Latitude weighting**: cos(lat) / mean(cos(lat))
- **`use_residual: false`** — модель предсказывает абсолютное поле, НЕ дельту
- **Static channels**: z_surf, lsm → carry-forward при AR
- **Forcing channels**: нет (time features не используются как forcing)

### 19 переменных модели
| # | Переменная | Описание |
|---|-----------|----------|
| 0 | t2m | Температура на 2м |
| 1 | 10u | U-комп. ветра 10м |
| 2 | 10v | V-комп. ветра 10м |
| 3 | msl | Давление на уровне моря |
| 4 | tp | Осадки |
| 5 | sp | Приземное давление |
| 6 | tcwv | Водяной пар (столб) |
| 7 | z_surf | Геопотенциал поверхности (static) |
| 8 | lsm | Маска суша/море (static) |
| 9–13 | t@850, u@850, v@850, z@850, q@850 | 850 гПа |
| 14–18 | t@500, u@500, v@500, z@500, q@500 | 500 гПа |

### Результат обучения
- **Skill** (1 − RMSE_model/RMSE_persistence): **75.82%** на ROI
- **t2m RMSE** на тесте (Jan 2023): **~1.40°C** на +24h (по региону)
- **ACC** (anomaly correlation): 0.987 на +6h → 0.95 на +24h

## Пост-обработка (correction chain)

### 1. Lapse-rate коррекция
- Грид высота z_surf ≈ 352 gpm, станция Емельяново = 287 м
- ΔT = (352 − 287) × 6.5e-3 = **+0.42°C** (фактически применяется +0.62°C с учётом интерполяции)
- Применяется ко всему полю

### 2. Learned MOS (Model Output Statistics)
- **Алгоритм**: sklearn `HistGradientBoostingRegressor` (max_iter=500, max_depth=8, lr=0.05)
- **Цель**: `bias = station_t2m − ERA5_t2m` (предсказываем систематическую ошибку)
- **Features (20)**: t2m, dewpoint, wind_speed, wind_dir_sin/cos, sp, cloudcover, shortwave_radiation, precipitation, hour_sin/cos, doy_sin/cos, solar_elevation, dewpoint_depression, t2m_lag6h, delta_t2m_6h, station_lat/lon/elev
- **Данные**: ERA5 (Open-Meteo Archive API) + наземные станции NOAA ISD-Lite, 2016–2024
- **Что делает при инференсе**: для каждой из 19 станций предсказывает bias, находит ближайший узел грида, прибавляет коррекцию. Для узлов с несколькими станциями — усредняет.
- **19 станций** в радиусе ~270 км от Красноярска (все активные ISD в регионе):
  - **В городе (< 30 км)**: только 295710 Minino (≈Ветлужанка, 11 км от центра)
  - **Рядом (30-100 км)**: Емельяново (аэропорт), Шумиха, Кача, Сухобузимское, Кемчуг
  - **Далеко (>100 км)**: Ачинск, Канск, Абакан (270 км!), Богочгол (208 км), etc. — 13 штук
- **Результат**: Test MAE = **1.32°C** (на данных 2024 года)
- **КРИТИЧЕСКАЯ ПРОБЛЕМА**: MOS корректирует только 18 узлов грида из 2,501 регионального (0.7%!)
- **Городская станция 295740 «Красноярск» (WMO 29574) — МЕРТВА с 1996 года.** В ISD больше нет городских станций
- **Городские ПНЗ** (Ветлужанка, Черёмушки, Северный, КрАЗ, etc.) мерят загрязнители, НЕ стандартные метеопараметры; данные нет в ISD

### 3. Усвоение данных (Data Assimilation) — есть в коде, НЕ используется в live
- **Nudging**: `x_new = x_old + α·(obs − x_old)`, α = 0.25
- **Optimal Interpolation**: B-матрица Гауссова, K = B·Hᵀ·(H·B·Hᵀ+R)⁻¹, анализ x_a = x_b + K·(y − H·x_b)
- Работает в `predict.py` для ретроспективных тестов, но не интегрировано в live pipeline

## Проблема: систематический холодный bias

### Конкретный пример (3 апреля 2026)

| Время UTC | Шаг | GNN (°C) | Open-Meteo (°C) | Яндекс (°C) | Факт станция Ветлужанка |
|-----------|-----|----------|-----------------|-------------|------------------------|
| Apr3 00:00 | +6h | **−0.4** | +2.8 | +3 (утро) | **+4.4** |
| Apr3 06:00 | +12h | +2.2 | +4.3 | +4 (день) | — |
| Apr3 12:00 | +18h | +2.5 | +3.7 | +5 (вечер) | — |
| Apr3 18:00 | +24h | +1.2 | +2.4 | +3 (ночь) | — |

**Step 1 (+6h): GNN = −0.4°C, факт = +4.4°C → ошибка ~5°C!**

Даже после коррекций (lapse +0.62°C + MOS) модель промахивается на 3–5°C в холодную сторону.

### Средние смещения (по 12 горизонтам vs Open-Meteo)
- **Температура**: GNN холоднее на ~1.2°C (MAE vs OM = 1.66°C)
- **Ветер**: GNN занижает скорость в среднем на ~3.3 м/с (step 2: GNN 5.4 vs OM 16.2 м/с!)
- **Давление**: GNN msl ~1012–1022 гПа vs OM sp ~980–997 гПа (~20 гПа разница — разные переменные: msl vs sp)

### Анализ причин
1. **Сглаживание (spectral bias)**: GNN, обученная на MSE, стремится к среднему → занижает амплитуду суточного хода и экстремумы
2. **ERA5 bias**: ERA5 сам имеет систематическую ошибку для горного/континентального климата
3. **Грубый грид**: 0.25° ≈ 28 км — не разрешает городской эффект, долинные инверсии
4. **MOS покрывает 0.7% узлов**: коррекция 18 точек из 2,501 — капля в море
5. **Нет time features**: модель не знает час/сезон → не улавливает суточный цикл
6. **Forcing не используется**: при AR-rollout модель не получает внешнего форсинга (инсоляция, etc.)
7. **Ветер сглажен**: 10u/10v на 28-км сетке не ловят порывы, орографическое усиление

## Что мы хотим

### Основная задача
Улучшить точность прогноза **температуры** (t2m) для Красноярска (56.01°N, 92.88°E) на горизонтах +6h...+72h.

### Целевые метрики
- t2m MAE ≤ 1.0°C на +24h (сейчас ~1.5–2°C)
- Устранить систематический холодный bias (сейчас −1...−5°C)
- Улучшить суточный ход (амплитуда день/ночь)

### Ограничения
- Обучение на одном GPU (16–24 GB VRAM)
- Данные ERA5 открыты (WeatherBench2, CDS)
- Станционные данные NOAA ISD — открыты
- Нет доступа к мезомасштабным моделям (WRF/COSMO) для обучения
- Хотим решение, которое можно реализовать за 1–2 недели

## Вопросы

1. **Что кардинально улучшит прогноз для региона?** Какой один приём даст наибольший прирост качества?

2. **Как эффективно распространить MOS-коррекцию на всё поле?** Сейчас MOS работает в 18 точках из 2,501. Варианты:
   - Пространственная интерполяция bias (kriging, IDW, radial basis)?
   - Grid-level обучение MOS (ERA5 как "модель", анализ как "факт")?
   - Нейросетевой постпроцессор (маленький CNN поверх GNN)?

3. **Time features / forcing**: стоит ли добавить sin/cos(hour), sin/cos(DOY), солнечную инсоляцию как дополнительные входные каналы? Или как forcing при AR? Как это координально меняет качество суточного хода?

4. **Усвоение данных в live**: как интегрировать станционные наблюдения в live pipeline? Подправлять начальное состояние (analysis) или корректировать на каждом AR-шаге?

5. **Архитектурные изменения**: стоит ли пробовать:
   - `use_residual: true` вместо `false` (предсказывать дельту)?
   - Увеличить obs_window с 2 до 4 (больше истории)?
   - Attention вместо InteractionNet?
   - Ensemble из нескольких моделей?

6. **Ветер**: GNN систематически занижает скорость ветра. Это fixable через MOS/постпроцессор, или нужно менять архитектуру/loss?

7. **Hybrid loss**: MSE + spectral loss, MSE + perceptual loss — помогает ли это от сглаживания?

8. **Практический roadmap**: если есть 2 недели и 1 GPU, какие 3–5 изменений дадут максимум?
