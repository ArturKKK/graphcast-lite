## 2. Адаптивный радиус IDW per-station

**Что сейчас:** при пространственной интерполяции станционных поправок на узлы сетки используется **один глобальный радиус** `L = 100 км` (подобран на эксперименте «радиус × дисперсия», см. таблицу в `docs/diploma/diploma.tex`).

**Почему это плохо:**

- В Сибири станции стоят с шагом 300-500 км → радиус 100 км оставляет «дыры» между станциями (узлы сетки между ними получают почти нулевую поправку, даже если соседние станции согласно «должна быть +2 °C»).
- В Европейской части — шаг 50-100 км → радиус 100 км даёт слишком сильное размазывание, теряется локальность (городские особенности «затираются» соседями).

**Что надо сделать:**

Заменить глобальный `L` на **per-station** `L_i`, вычисляемый детерминированно по плотности соседей:

```python
def compute_adaptive_bandwidth(stations, k=5, alpha=1.0, L_min=50.0, L_max=400.0):
    """
    L_i = alpha * mean distance to k nearest neighbors of station i.

    Аргументы:
        stations: list of (lat, lon)
        k: сколько ближайших соседей учитывать (3-7)
        alpha: множитель (0.8-1.5)
        L_min, L_max: clamps для устойчивости

    Возвращает: dict {station_idx -> L_km}
    """
    from sklearn.neighbors import BallTree
    coords = np.radians(np.array([(la, lo) for la, lo in stations]))
    tree = BallTree(coords, metric="haversine")
    dists, _ = tree.query(coords, k=k+1)  # +1 because first is self
    # dists in radians; convert to km
    L = alpha * dists[:, 1:].mean(axis=1) * 6371.0
    return np.clip(L, L_min, L_max)
```

В коде интерполяции (`src/postprocessing/mos_correction.py:_idw_interpolate_bias()` и/или `src/assimilation/optimal_interpolation.py`) заменить `L` на массив `L_i` по индексу станции.

Это **детерминированный расчёт без переобучения** — просто посчитать один раз при загрузке реестра станций и закешировать.

**Чего ждать:**

- **В разрежённой Сибири** поправка от одной станции «дотянется» дальше (L_i ~300 км вместо 100), накрывая узлы, к которым раньше не доходила.
- **В плотной Европейской части** поправка останется локальной (L_i ~50-80 км), не «размазывая» специфику городов.
- **Ожидаемый выигрыш** на станциях в редко-покрытых регионах: 5-15% улучшение rmse_t2m. На плотных регионах — нейтрально или чуть хуже (но это в пределах шума).

**Опционально:** ещё более продвинутый вариант — обучаемый `L_i` через нейросеть (станция → радиус), но это уже не «детерминированно посчитать», а отдельный обучаемый блок.

## 3. Сравнить глобальные модели v2 (19 каналов) и v3 (33 канала)

**Зачем:** v3 используется как база для дообучения 33-канальной региональной модели; хочется знать, действительно ли она сильнее v2 по общим полям, а не только «новее».

**Что нужно (при следующем перезапуске VM, когда `/data` восстановится из S3):**

1. `global_512x256_extra_2010-2021_07deg` (43 ГБ) — уровни @250/@1000 для глобальной сетки. Восстанавливается из S3 автоматически; **не удалять** при чистке диска (в отличие от российских датасетов).
2. Собрать 33-канальный глобальный датасет (~64 ГБ, 2–3 ч; базовые 19 каналов подключаются симлинком, копируются только 14 новых):

   ```bash
   python scripts/build_v3_extra_with_time.py \
       --base-dir  /data/datasets/wb2_512x256_19f_ar \
       --extra-dir /data/datasets/global_512x256_extra_2010-2021_07deg \
       --out-dir   /data/datasets/wb2_512x256_33f_v3
   ```
   (флаги уточнить: `python scripts/build_v3_extra_with_time.py --help`)

3. Два прогона на одном тестовом окне (~1 ч):

   ```bash
   # v2 — 19 каналов
   python scripts/predict.py experiments/wb2_512x256_19f_ar_v2 \
       --data-dir /data/datasets/wb2_512x256_19f_ar \
       --split test_only --ar-steps 4 --max-samples 200 --per-channel
   # v3 — 33 канала
   python scripts/predict.py experiments/wb2_512x256_33f_ar_v3 \
       --data-dir /data/datasets/wb2_512x256_33f_v3 \
       --split test_only --ar-steps 4 --max-samples 200 --per-channel
   ```

**Бюджет диска (лимит платформы ~240 ГБ!):** глобальный 82 + extra 43 + 33f-датасет 64 = 189 ГБ. Значит `multires_krsk_19f_merge` (76 ГБ) на этой VM **держать нельзя** — либо удалить после региональных расчётов, либо делать сравнение на отдельной VM.

**Как интерпретировать (важно):** сравнение не изолирует эффект уровней давления — v3 отличается от v2 сразу несколькими факторами: 33 канала против 19, curriculum до 8 авторегрессионных шагов против 4, остаточная формулировка, веса каналов в функции потерь, инъекция шума. Сравнивать можно только по **общим 19 полям**. Поэтому:

- **v2 vs v3** → справочное сравнение отправных точек («базой для региональной 33-канальной модели взята более сильная глобальная модель»);
- **научный вывод о пользе уровней 250/1000 гПа** → из эксперимента `multires_krsk_33f` против `multires_nores_freeze6`, где схема обучения выровнена специально (max_ar=4, 32 эпохи, freeze6, тот же сид, без весов каналов и шума).
